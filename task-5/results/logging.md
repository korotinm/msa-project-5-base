# Способ отправки логов

Диаграмма: [C4_Container.puml](C4_Container.puml) (оранжевые связи).

## Задача

Монолит пишет логи в файл на VM, новый batch-сервис будет в k8s. Нужно собрать всё в одном месте
и находить причину сбоя по конкретному файлу. Облачные сервисы не используем, стек из курса — ELK.

## Решение

**Filebeat → Logstash → Elasticsearch, поиск в Kibana.**

- Приложения пишут JSON в stdout (batch-сервис) или в файл (WildFly) и ничего не знают о лог-системе.
- Filebeat читает файлы и stdout контейнеров (DaemonSet в k8s, агент на VM монолита).
- Logstash парсит, маскирует чувствительные значения и буферизует, если Elasticsearch недоступен.
- В каждую запись кладём `file_id`, `job_id`, `warehouse`, `service`, уровень и стектрейс; `file_id` и `job_id` попадают через MDC.
  Так по одному `file_id` видна вся цепочка: приём файла, очередь, чанки, ошибки.
- Индекс на сутки, хранение 14 дней в быстром хранилище, потом удаление (ILM).

## Почему не другие варианты

- **Appender Logback → Logstash напрямую:** приложения начинают зависеть от доступности лог-системы, плюс не подходит для WildFly без доработок.
- **Filebeat → Elasticsearch без Logstash:** проще, но нет буфера и негде централизованно маскировать данные.
- **Fluent Bit + Loki:** легче, но это второй инструмент поиска рядом с ELK, а не стек курса.

## Риски

Logstash и Elasticsearch требовательны к ресурсам, в пик логов в 2–3 раза больше: нужно следить за объёмом и не включать DEBUG в проде.
Корреляция работает только если везде есть `file_id`, это проверяем на код-ревью.
